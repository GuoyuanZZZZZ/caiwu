# 差旅费制度审核平台：可直接演示的完整案例

本文给你一个可以直接在本地 GUI 中复现的端到端案例，适合给业务同事演示 MVP。

## 1) 案例目标

演示以下能力：
- 导入制度规则
- 导入报销数据
- 一键执行自动审核
- 查看 PASS / FAIL / MANUAL_REVIEW
- 导出审核结果

## 2) 使用文件

- 制度：`data/sample_rules.csv`
- 报销：`data/sample_claims.csv`

## 3) 操作步骤（GUI）

1. 启动程序：`python main.py`
2. 打开“制度管理”页，点击“导入制度文件”，选择 `sample_rules.csv`
3. 打开“报销导入”页，点击“导入报销文件”，选择 `sample_claims.csv`
4. 打开“自动审核”页，点击“执行审核”
5. 打开“审核结果”页，筛选 `ALL` 查看全部结果
6. 点击“导出 Excel”，导出 `audit_results.xlsx`

## 4) 这个案例里每条报销的预期结果

| claim_id | 预期状态 | 主要原因 |
|---|---|---|
| C001 | FAIL | 命中机票规则：无事前审批 + 超金额 + 舱位不符；且存在重复嫌疑 |
| C002 | PASS | 酒店金额未超限 |
| C003 | PASS | 餐补金额未超限 |
| C004 | FAIL | 高铁金额超限 + 席别不符 |
| C005 | MANUAL_REVIEW | 与 C001 构成疑似重复，且存在特批标记 |
| C006 | FAIL | 出租车金额超默认上限 |

> 说明：当前 MVP 的重复报销规则会将重复项标记为人工复核；若同时命中其他失败规则，以规则引擎当前实现输出为准。

## 5) 预期审核摘要

- 总记录数：6
- PASS：2
- FAIL：3
- MANUAL_REVIEW：1

## 6) 演示话术（给业务方）

你可以按下面说法演示：

1. “我们先导入公司制度，系统会把规则落到本地数据库。”
2. “再导入本次待审报销明细。”
3. “点执行审核后，系统按职级、费用类型、城市等级、舱位优先级自动匹配制度条款。”
4. “有违规会直接给出问题说明和制度依据；有特批或疑似重复会转人工复核。”
5. “最后可以一键导出结果给财务复核和留档。”
